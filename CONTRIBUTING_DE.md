# Mitwirkung an Sasogine

Vielen Dank für das Interesse an Sasogine.

Sasogine ist als Open-Source-Projekt öffentlich verfügbar. Die
Kernentwicklung und die architektonische Ausrichtung werden derzeit
jedoch vom Projektinhaber gepflegt.

## Fehler melden

Bug Reports sind willkommen.

Reproduzierbare Fehler in Sasogine sollten über GitHub Issues gemeldet
werden.

Eine Fehlermeldung sollte nach Möglichkeit folgende Informationen
enthalten:

-   Sasogine-Version
-   .NET-Version
-   Betriebssystem
-   verwendetes Rendering-Backend
-   Schritte zum Reproduzieren
-   erwartetes Verhalten
-   tatsächliches Verhalten
-   relevante Exceptions oder Stack Traces
-   möglichst kleinen Beispielcode zur Reproduktion

## Fragen

Fragen zu Sasogine, zur Architektur, zu APIs oder zur Verwendung sollten
über GitHub Discussions gestellt werden.

GitHub Issues sollten hauptsächlich für tatsächliche Fehler und
eindeutig erkennbare Probleme verwendet werden.

## Ideen und Vorschläge

Ideen und Feature-Vorschläge sind über GitHub Discussions willkommen.

Vorschläge können die zukünftige Entwicklung beeinflussen. Das
Einreichen eines Vorschlags bedeutet jedoch nicht automatisch, dass
dieser umgesetzt wird.

Architektonische Entscheidungen verbleiben beim Projektinhaber von
Sasogine.

## Pull Requests

Externe Pull Requests gehören derzeit nicht zum normalen
Entwicklungsablauf von Sasogine.

Vor vorgeschlagenen Änderungen am Quellcode sollte zunächst eine
Discussion oder ein Issue eröffnet werden.

Die Implementierung und Integration von Änderungen erfolgt durch den
Projektinhaber, um die Konsistenz der Architektur und der öffentlichen
API sicherzustellen.

## Coding Standards

Sasogine verwendet eigene Coding- und Architekturkonventionen, die auf
den etablierten .NET-Standards basieren.

Siehe:

-   `CODING_STYLE_DE.md`
-   `PROGRAMMING_ARCHITECTURE_GUIDELINES_DE.md`

Diese Regeln sollten auch bei Codebeispielen, Fehlerreproduktionen und
technischen Vorschlägen berücksichtigt werden.

## Dokumentation

Korrekturen und Verbesserungsvorschläge zur Dokumentation sind über
GitHub Issues oder Discussions willkommen.

Dazu gehören beispielsweise:

-   fehlerhafte Dokumentation
-   fehlende API-Erklärungen
-   veraltete Beispiele
-   Schreibfehler
-   unklare Beschreibungen

## Community

Sachliche technische Diskussionen sind willkommen.

Sasogine soll eine fokussierte Entwicklung behalten und gleichzeitig
einen offenen Bereich bieten, in dem Nutzer Fehler melden, Fragen
stellen und Verbesserungsvorschläge einbringen können.
